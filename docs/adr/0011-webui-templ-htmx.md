# ADR 0011: WebUI — templ + HTMX + Tailwind

## Status

Accepted

## Context

RezusCloud's management plane needs a web interface for operators. The
rejected alternative — a Vue/React SPA with gRPC-Web, Monaco, JSONForms,
Storybook — is enterprise-console complexity inappropriate for a personal
cloud. See [`../architecture-history/`](../architecture-history/README.md).

RezusCloud lives above `talosctl`/`kubectl` (see [ADR 0001](0001-what-rezuscloud-is.md)).
The WebUI is the operator's window onto the management plane — it consumes the
REST API, renders state, and triggers orchestration actions. It is not a
Kubernetes console.

## Decision

**Server-rendered HTML with HTMX**, generated by Go:

- **templ** for type-safe Go HTML templates (no string interpolation).
- **HTMX 2.x** for partial page swaps and SSE-driven live updates.
- **Alpine.js 3.x** for lightweight client-side reactivity (dropdowns, modals).
- **Tailwind CSS v4** for styling, matching the RezusCloud design system.
- **REST API as the sole transport** — no gRPC-Web bridge, no separate API
  for the browser.
- **No Node.js build** in production — templ generates Go at build time, CSS
  is pre-compiled.

### What the WebUI shows

The WebUI surfaces tenant orchestration state read-only (see
[ADR 0015](0015-read-only-surfacing.md)) and triggers orchestration actions
(create tenant, scale node group, run upgrade, apply config patch). It does
not duplicate `kubectl` features (no pod exec, no in-cluster resource editing).

## Consequences

- **One language (Go)** for the entire management plane — frontend and backend.
- **No SPA hydration, no client-side routing.** Full-page swaps via HTMX.
- **Smaller attack surface** (no Monaco, no JSONForms, no dynamic eval).
- **HA-ingress compatible** (works in a Home Assistant iframe).
